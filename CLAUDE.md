# WorkPulse

Single-user office record: log work, run task timers, clock in and out, and close the day with an AI standup and
an end-of-day timesheet. Logs can be drafted from the day's git commits and Claude Code prompts. React 19 SPA served
by a thin Express server. All data lives in browser localStorage, with optional AI (Claude Code or Gemini) and Google
Sheets sync. (Originally generated by Google AI Studio; the UI was redesigned as "v2" in Nov 2026.)

## Architecture

- `src/App.tsx` owns **all** state (logs, backlog, workdays, projects, tags, settings, dialogs) and every handler. Screens and
  dialogs are presentational and receive props and callbacks. A **1-second `setInterval`** adds elapsed seconds to running
  tasks; the backlog is saved every 30 s and when the tab is hidden or closed, not every tick.
- **Save engine** (`src/utils/persist/engine.ts`, `getEngine()` in `storage.ts`): **every write of the app's data goes through it.** A failed save is kept and retried (`usePersistence`: every few seconds and when the window returns), related keys are written as one group (`saveGroup`, all or nothing), `workpulse_meta` (profile id, revision, list of saved keys) is written last as advice, and `SaveStatusBanner` stays on screen while anything is not saved. **A key whose stored value could not be read is blocked (`engine.block`) and never overwritten**, so an empty fallback list cannot replace real data; the banner offers restore or "start empty" for it, and an import unblocks with `discardPending`. Only one window may write (`writerLock.ts`, Web Locks: a second window is read-only until "Use this window"). `flushAll()` runs the registered flushers (in-memory timers) then retries; it runs before a crash reload and when the Electron shell asks (quit, suspend, lock, session end). `storageUsageBytes` / `storageNearlyFull` (80 % of 5 MB) feed System status.
- **Disk copies** (`~/WorkPulse/backups/<app address>/`, folder from `src/server/dataDir.ts`; override with `--data-dir=temp|<path>` or `WORKPULSE_DATA_DIR`): the browser's storage can be wiped, so the data keys in `src/utils/persist/keys.ts` (`DATA_KEYS`, no device-only keys) are mirrored to disk. Pieces: `src/server/localCopy.ts` (temp file then rename, `prev.json`, checksum verified on read, 14 daily and 10 safety copies), routes `GET/PUT /api/disk-copy` and `POST /api/disk-copy/safety` (behind `activityGuard` plus an Origin check), `src/utils/persist/diskMirror.ts` (sends 3 s after a save-counter change, at most every 15 s, backs off on failure, pauses when read-only, blocked, not ready or no real data; a copy of another profile is a `conflict` until the user chooses), `src/utils/persist/reconcile.ts` (`decide`: none, take-over, `offer-restore` for empty or behind, `restore-keys` for blocked keys) and `src/hooks/useDiskCopy.ts` (the restore offer; the page decides, the server only stores). Restore replaces data only after the user agrees, except blocked keys.
- **Data doctor** (`src/utils/dataDoctor.ts`): runs at load (not while a key is blocked), and after an import or restore. Fixes repeated or missing ids, impossible dates, minutes and task seconds, logs pointing at a missing project (placeholder project), and a clock-out before its clock-in. It never deletes a record or changes valid text, and a second run changes nothing. Repairs are noted in `workpulse_repairs` (newest 50, `recordRepairs`) for System status.
- **Errors, health and the log file**: `ErrorBoundary` (`src/components/ui/`) wraps the root, the clock, each screen, the edit-task dialog and widgets, with `reportUnhandled` for window errors and rejected promises (`src/utils/health/reportError.ts`; the same error is reported once, at most 20 a session). Reports go to the health registry (`src/utils/health/registry.ts`: one entry per subsystem such as `storage`, `diskCopy`, `server`, `sheetSync`, `phone`, `sheetBackup`, `dayClose`, `email`, `activity`, `app`, with when it last worked, since when it fails and a warn/critical threshold per subsystem in `THRESHOLDS`) and, through `src/utils/health/clientLog.ts` and `POST /api/client-log` (rate limited, fields cleaned in `src/server/clientLog.ts`), to the rotating log file in `~/WorkPulse/logs/` (`src/shell/fileLog.ts`, 1 MB, 3 files; every line passes `redact.ts`). **The log holds what happened and where, never what the user wrote.** `src/utils/systemStatus.ts` (`buildSystemStatus`, pure) turns all this into the rows of Settings -> System status (`components/v2/settings/SystemStatusSection.tsx`; guide in `docs/system-status.md`). A subsystem that never reported to the registry reads as working.
- **Network layer** (`src/utils/net/`): `requestJson` (`http.ts`) is the one way the page calls its own server. It never throws, always times out (`timeouts.ts`, `scriptTimeouts.ts`; client limits are a little longer than the server's), and returns a kind (`timeout`, `server-down`, `aborted`, `bad-response`, `http`) with a plain sentence and `retryable`. `backoff.ts` (`nextDelay`, `BACKOFF`) spaces retries, `serialQueue.ts` keeps calls one at a time, and `src/server/scriptProxy.ts` makes the Google call with a time limit and plain failures.
- **Storage keys**: `src/utils/storage.ts` reads and writes localStorage keys `workpulse_logs`, `workpulse_backlog`,
  `workpulse_projects`, `workpulse_tags`, `workpulse_settings`, `workpulse_workdays`, `workpulse_standups`. Device-only keys outside the data keys: `workpulse_meta`, `workpulse_journal`, `workpulse_heartbeat`, `workpulse_repairs`, `workpulse_autoday_dismissed`, `workpulse_activity_notice`.
  `loadStoredData()` falls back to `src/data/seedData.ts` and maps old theme ids. It does **not** roll tasks over (below). Logs are not written until the first change, so a fresh profile has no `workpulse_logs` key yet.
- **Data types**: `src/types.ts` defines `WorkLog`, `BacklogTask` (stages: planned → in_progress → paused/blocked → done),
  `Project`, `AppSettings`, `WorkdayRecord`/`Workdays`, `ThemeId` and `AppNavTab`.
- **Server** (`server.ts`) is a thin proxy with no database:
  - `POST /api/gemini/generate` handles AI standup text (`src/utils/aiGenerator.ts` builds the prompt and has offline templates)
  - `POST /api/synthesize-eod` groups tasks by project × status and writes each group with AI, with a template fallback
  - Both take `provider`: `'claude'` (default) runs the user's `claude -p` via `runClaudeJson` (`src/server/aiWriter.ts`; answers 403 unless
    `isLocalOnlyRequest`, like the activity routes; failures return a plain `notice` and the client uses the template), `'gemini'` runs the
    Gemini cascade. `AppSettings.activityAi` is the one "AI writer" setting (Settings → AI) for standup, end of day and suggestions; `'none'`
    makes no server call. The Gemini key is sent only when Gemini is chosen.
  - `POST /api/sheets/proxy` forwards to the user's Google Apps Script URL (avoids CORS). The script is composed in `src/utils/googleAppsScriptTemplate.ts` from `src/utils/appsScript/` (see **Phone page and evening email**)
  - `POST /api/activity/scan` and `POST /api/activity/suggest` read the user's git commits and Claude Code history and group them with an AI (see **Activity suggestions** under Gotchas)
  - `POST /api/client-log` (page errors into the log file) and `GET/PUT /api/disk-copy`, `POST /api/disk-copy/safety` (disk copies, see **Disk copies**); same guard and Origin check
  - `POST /api/pick-folder` opens the Windows folder dialog (`src/server/folderPicker.ts`: PowerShell with a hidden TopMost owner
    form, 5 min timeout, killed if the client disconnects, one at a time else 409, non-Windows 501). Behind `activityGuard` plus an
    `Origin` check (`isAllowedPickOrigin`). Tests and smoke never open a real dialog (the smoke check stubs the route)
  - `GET /api/health`
  - Dev mode mounts Vite as middleware; HMR shares the same HTTP server and port
- **Shell and screens** (`src/components/v2/`): `AppHeader` (brand, `NavTabs`, Search, the one **next action** button) with
  `ClockBand` inside it, then one of four screens (`AppNavTab`: `today`, `tasks`, `history`, `settings`), and `BottomNav`
  under 640 px. The tabs read **Do** (`today`) and **Plan** (`tasks`): tab = verb, group = date, the stage shows on the row.
  - `today/`: `TodayScreen` = `TodayTasks` (quick add; Enter = planned, Shift+Enter = started; `#project` picks the project),
    `SuggestionsCard` (the compact activity panel) and `TodayLog` (quick log, "Details" opens `LogFormDialog`, Standup, Sync,
    End my day). Rows are `TaskRow` (one primary button: Start / Pause / Resume / Log it, the rest in the `RowMenu` ⋯) and `LogRow`.
  - `tasks/TasksScreen` (the Plan tab): one column with an **Open | Done** switch. Open lists every pending task once, whatever its stage,
    under its date group: Overdue ("Move all to today"), Today, Tomorrow, This week (2 to 6 days out), Later; rows in multi-date groups say
    "due …" (`groupTasks` in `src/utils/taskSections.ts`, `DayBlock` in `tasks/EarlierGroup.tsx`, `dayHeading` in `src/utils/taskDates.ts`).
    Done = the last 7 days; select done tasks → "Write timesheet" (the EOD synthesizer). Add with project and due date, project filter.
    Do shows a "N more overdue tasks on Plan" line for older planned tasks.
  - `history/`: `HistoryScreen` (one toolbar on top: From and To dates with Today / Yesterday / Last 7 / Last 30 days, Search, Project, Sync, Export; then `WeekStrip`,
    a summary line, and one list grouped by date). **A range always has a start and an end** (one day = From equals To; App keeps `{ from, to }`, `onSelectDay` / `onSelectRange`).
    Each day group shows its clock times, worked / logged / tracked figures, the **done tasks and logs together**, and its saved standup. Search and the project filter
    stay inside the chosen dates unless "all dates" is ticked. Export follows the list (CSV = logs; Markdown = days with tasks, logs and standups). Pure part: `summarizeRange`,
    `rangeToMarkdown` in `src/utils/historyDay.ts`; filter in `src/utils/logFilter.ts`; selected logs → Standup / Copy as Markdown / CSV (`src/utils/exportLogs.ts`).
  - Settings is `src/components/SettingsView.tsx` (one page with anchors) using `settings/ThemePicker` and `settings/ProjectsSection`.
  - Dialogs: `LogFormDialog` (add/edit a log), `ClockInDialog` ("I came in at…"), `endday/EndDayDialog`, plus the kept
    `AiStandupModal`, `EodSynthesizerModal` (its body is `EodPanel`, reused by End my day), `SearchPaletteModal` (Ctrl+K; picking a
    log opens it in History), `ActivitySuggestionsDialog`, `LightboxModal`, `PlanYourDayDialog` (below).
- **Office clock**: `workpulse_workdays` is `Record<local date, { clockIn: ISO; clockOut?: ISO }>`; the date is the local date
  of `clockIn`. Maths in `src/utils/workday.ts` (`clockState` phases off / calm / near (≤60 min left) / due (≤15) / over / out,
  `openWorkdayBefore`, `currentWorkday`, `clockIn`, `clockOut`, `resumeWorkday`); target `AppSettings.workdayHours` (absent = 8;
  outside 1-16 it is dropped on load and import). The clock and timers are independent: starting a timer never clocks in. Clocking out (band button, End my day, or the automatic one) pauses every running timer at the clock-out time (`pauseRunningAt` in `segments.ts`; seconds counted after a past-stamped automatic clock-out are taken back); Resume of the day does not restart them. A day
  still open from an earlier date (working past midnight, or a forgotten clock-out) shows as "Clocked in since …" in the band and
  "no clock-out" in History; a plain timer or an open day closes nothing by itself (only the safety net and day close in **The automatic day** do, and a manual clock-out is never undone). While today has no record, End my day and the next action work on
  that open day (`currentWorkday`), so it can be clocked out. "I came in at" a time later than now means yesterday (`chosenClockIn`).
- **The automatic day** (`AppSettings.autoDayEnabled`, absent = on; design in `docs/superpowers/specs/2026-11-16-automatic-day-design.md`). Three hooks, started once data is loaded:
  - `useHeartbeat` (`src/utils/heartbeat.ts`) writes `workpulse_heartbeat` every 30 s, on focus and on pagehide, and hands back the beat of the previous run: after a shutdown it says when the PC was last alive.
  - `useAutoDay` (`src/utils/autoDay/`): the **start-of-day popup** (`startPrompt.ts`; suggests a clock-in time and auto-confirms; never clocks in without it; dismissals in `workpulse_autoday_dismissed`) and the **automatic clock-out safety net** (`autoClockOut.ts`: 60 min idle past the workday, or an earlier day never closed, stamped at the last time the PC was alive and never past 23:59). **Busy time** (`busy.ts`): a manual log with a start time and a duration counts as busy, and no clock-out fires inside it.
  - `useDayClose` (`src/utils/jobs/journal.ts`): two minutes after a clock-out (a quick Resume cancels it) it reads that day's activity (only after the data notice is accepted), adds logs with **`WorkLog.origin: 'auto'`** (an "Auto" badge; manual logs have none), marks covered done tasks as logged, and toasts with **Undo**. `workpulse_journal` (device-only, newest 60 days) records each closed day (`done` or `empty`), so a day is handled once and a reload never repeats it; days missed while the PC was off are caught up for up to 7 days; failures retry after 1, 5, 15, then 60 min. It never touches logs written by hand.
- **Timer segments and overs**: `BacklogTask.segments` (`{ start, end? }[]`, `src/utils/segments.ts`) is appended when a timer
  starts and closed when it pauses or finishes. On pagehide the saved copy closes open segments; load reopens them for running
  tasks (`ensureOpenSegment`). A tick gap over 120 s (sleep, frozen tab) adds no seconds and splits the open segments at the
  gap (`splitSegmentsAtGap`), so sleep is not drawn as work. `buildOvers` turns them into the Chase band's overs strip (an hour = six 10-minute balls coloured by
  the project that ran longest). Segments only draw the strip; durations still come from `elapsedSeconds`.
- **Task dates and no rollover**: a pending task keeps its `dueDate` for good and is listed under that date (Earlier / Today /
  Upcoming). Nothing moves tasks to today by itself. A task changes date only when the user moves it ("Move to today" on a row,
  "Move all to today" on a group, or Plan your day; `moveTasksToDay`, App `handleMoveToToday` with Undo) or starts, resumes or adds
  it as started (it then counts as today). A running timer left across midnight moves to the new date (`moveRunningToDay`, on load
  and when the date changes). Pure helpers: `src/utils/taskDates.ts`, `taskSections.ts`, `todayTasks.ts`.
- **Plan your day** (`PlanYourDayDialog`, pure helpers in `src/utils/planYourDay.ts`): opens after the **first clock-in of a date**
  (not on Resume, not for "I came in yesterday at"), and from a button on Today's tasks. Lists tasks from the phone (first clock-in
  only), earlier pending tasks to carry (ticked, except blocked) and a box for new tasks (one per line, `<project name> <task>`: `parsePlanLines` takes the active project the line starts with, longest name wins, or a unique first-word prefix; the first word completes to the full name; a line with no project is flagged and blocks Start the day). Skip changes
  nothing; "Start the day" does one functional state update (`handleStartDay`).
- **Phone page and evening email** (optional; needs the Sheet script at version 3; user guide and manual checklist in
  `docs/phone-and-email-setup.md`). The script serves a PIN-protected page at `<exec url>?page=phone`, takes tasks typed on the phone
  into an inbox tab, and mails the owner a daily summary from a time trigger.
  - Desktop: `src/utils/phoneSync.ts` (snapshot of tasks/logs/workdays/projects for the Sheet, `mergeInbox`), `phoneApi.ts` (script
    calls through `/api/sheets/proxy`; PIN and token only in POST bodies), `phoneSettings.ts` (email time, device id, phone link,
    `keepDeviceSettings`), `src/hooks/usePhoneSync.ts` (push 5 s after a change and every 5 min while a timer runs; pull on load, focus
    and every 60 s; acks only after the tasks are saved). These files have no `window`, React or localStorage, except the hook.
    Settings: `components/v2/settings/PhoneEmailSection.tsx` (Set PIN / Change PIN / Reset phone access, link, evening email, test email).
    The desktop never keeps the PIN, only `AppSettings.phoneToken`. **Use one computer only.**
  - Script (version 3; plain ES5 in strings, no `let`/`const`/arrow functions): `src/utils/appsScript/core.ts` (PIN, token, lockout,
    state and inbox tabs, `phoneData`, `phoneAddTask`, `phoneOlderLogs`), `email.ts` (evening email, trigger), `phonePage.ts` (the page's
    HTML/CSS/JS and `servePhonePage`); the v2 log code stays in `googleAppsScriptTemplate.ts`. **Callable-function rule:** every
    top-level function whose name does not end in `_` can be called by anyone through `google.script.run` from the public phone page, so
    helpers end in `_`, and a test in `core.test.ts` pins the exact list of public names (a new public function must check the PIN or
    token itself and be added there). Tests run the real script text in `src/test/appsScriptHarness.ts` (fake Sheet, lock, mail,
    triggers, properties). Phone-page HTML is built only with escaping or `textContent`.
  - Device-only settings (never in backups): `phoneToken`, `phoneDeviceId`, `phoneSyncAt`, `phoneLastError`, `sheetBackupAt`, `sheetBackupError`, plus `geminiApiKey`
    and `lastBackupAt`. `keepDeviceSettings` keeps this computer's key, `lastBackupAt`, Sheet link and phone fields over an
    import, and its folder links when it has any (a computer with none takes the backup's) (a backup can never bring in a phone token). `emailEnabled` and `emailTime` ("HH:MM", default 18:00) do go in backups. `BacklogTask.fromPhone` marks tasks that came from the phone.
- **Sheet backup** (script version 4; user guide in `docs/phone-and-email-setup.md`): a full copy of the backup file
  (`buildSheetBackup` in `src/utils/sheetBackup.ts`: `buildBackup` compact, no log screenshots, no device-only fields) is kept in
  the Sheet tab `WorkPulse_Backup` as chunks of 40,000 characters, newest 3 versions, written under the lock with the
  `backupVersions` Script Property updated last (`src/utils/appsScript/backup.ts`; actions `saveBackup`, `backupInfo`,
  `loadBackup` are token-checked doPost actions, no new public function). Desktop: `phoneApi.ts` (`saveBackupToSheet`,
  `getBackupInfo`, `loadBackupFromSheet`), pure rules in `sheetBackup.ts` (`backupSignature` ignores ticking time, `shouldBackup`:
  30 s after a change, every 10 min while a timer runs, at load only if the last copy is over 1 hour old, 5 min wait after a
  failure, never for demo-only data via `hasRealData`), `src/hooks/useSheetBackup.ts` (one request at a time, not before load, not
  while `leavingRef` is set, quiet failures in `AppSettings.sheetBackupError`, device-only `sheetBackupAt`). Settings: `SheetBackupBlock`
  inside the Phone section; **Restore from the Sheet** downloads the current data, then goes through `handleImportBackup` like a
  file import (screenshots of logs still here are put back). Script below version 4 shows only the redeploy steps. The proxy body limit is 30 MB.
- **Clock-in WhatsApp message** (`AppSettings.clockInMessageEnabled`, absent = off and true = on; `clockInMessage`; Settings -> Office day; `src/utils/clockInMessage.ts`): after the
  first clock-in of a date, `handleClockIn` opens `web.whatsapp.com/send?text=...` in a new tab (`{time}` = the clock-in time). A link cannot name a
  group, so the user picks the chat and presses Send. Nothing is sent by the app, and no WhatsApp automation library is used (against its terms).
- **Evening email content**: also lists each log's sub-tasks (Sheet tab `WorkPulse_Recent` column `SubTasks`, from `SnapshotLog.subTasks`) and each
  task's project and tracked time. Needs script version 5 (re-paste and redeploy). From version 7 the "when I clock out" day email
  (`sendDayEmail`) is the same designed email for that date with the standup as its first section (`standupHtml_` in `email.ts`:
  marks drawn, bullets grouped per project); before, it was the bare standup text.
- **Email design** (script version 9): the email HTML in `email.ts` follows the references in `docs/email-designs/` (Main =
  clock-out, Week, Evening, Empty = test with no data, Phone = clock-out at 390 px; only the `<x-dc>` markup and the `<style>` matter).
  Tables and inline styles; the head `<style>` adds only hover and the `@media (max-width:480px)` sizes on the classes `wrap`, `hero`,
  `hn`, `card`, `sn`, `sc`. Check changes with `npx tsx scripts/render-email-templates.ts` against the references at 700 and 390 px.
  `LATEST_SCRIPT_VERSION` (`googleAppsScriptTemplate.ts`, read from `SCRIPT_VERSION`) drives the "newer script is out" notices in
  Test connection (`sheetsSync.ts`) and the Phone & evening email section.
- **One standup format, read the same in the app and the emails** (`src/utils/standupDoc.ts`, `parseStandup`): bold-only heading lines,
  `- *project:* point`, sub-points as indented `  - text`; points of one project gather under it per section. History draws it with
  `components/ui/StandupView.tsx`; the email script has its own ES5 copy (`standupDoc_`, `standupHtml_` in `email.ts`).
  **Change both together**: `standupDoc.test.ts` runs the same samples through both and fails if they differ. Every writer emits this
  format and writes from logs and done tasks merged (`standupEntries` in `standup.ts`; the Sheet's `rangeLogs_`): the PC AI prompt and
  template (`aiGenerator.ts`) and the Sheet's Gemini prompt and template (`standupPrompt_`, `templateStandup_`).
- **The Sheet sends clock-out emails** (script version 8, `SHEET_SENDS_SCRIPT_VERSION` in `phoneApi.ts`): `setEmail` with `when: 'clockout'`
  sets a timer every 15 min (handler `sendEveningEmail`; the fixed-time email is then never sent). It sweeps the last 3 days of
  `WorkPulse_Days` (pushed by `usePhoneSync` seconds after the clock-out), from the day it was switched on (`since`). Sending rules
  (`dueStandups_`, `sweepStandups_` in `email.ts`):
  - A closed day with a log goes at once when the PC's standup is in `WorkPulse_Standups`.
  - Otherwise it goes 10 min after the clock-out, with a standup the Sheet writes itself (`writeStandup_`) and saves under the same
    id, so a later PC standup replaces it.
  - A day never clocked out goes after midnight, and a Thursday also sends the week.
  - The Sheet's standup comes from Gemini when it can (`geminiStandup_`): the key is the Script Property `geminiKey` (from `setEmail`,
    never returned) and the models are `GEMINI_MODEL_CASCADE`. Any failure gives plain wording (`templateStandup_`), never a held email.
  - Writing happens outside the lock. `emailLog` keys are shared with the PC's `sendDayEmail`, so each email goes once.
  - Settings sends `when`/`geminiKey` only to a version 8 script; the user must press **Save email settings** once after redeploying,
    and again after changing the Gemini key.
  - `useDelivery` still sends from the PC when it can (usually the AI standup).
  - A new clock-out is pushed at once (`newClockOut` in `usePhoneSync`, no 5 s wait). A failed push is retried after 10, 10, 20
    and 40 s (`pushRetryDelay`), then by the minute cycle.
  - After a clock-out, `ClockBand` shows whether the Sheet has the day (`sheetSendState`: Sent / Sending / Not sent yet, with
    Send again). The failure text uses `--band-alert` (yellow on the Chase band, where red fails contrast).
  - Desktop: the page reports `pending` (Sheet behind) through `setSheetPending`. On Windows `query-session-end` while pending,
    `main.cjs` holds the shutdown (`preventDefault`) and sends `wp:final-push` (the page calls `pushNow`), waiting at most
    `FINAL_PUSH_MS` (8 s). It then flushes and `app.exit(0)`s. Sleep tries one push without holding.
- **Desktop app** (`electron/`, `scripts/build-desktop.mjs`, guide in `docs/desktop-app.md`): Electron shell that runs the bundled server on the fixed port 38417 (saved data belongs to the origin, so never change it). `npm run desktop:build` bumps the version and makes the Windows installer; the installed app updates itself from `~/wp-release` (`electron-updater`, generic feed on 127.0.0.1:38418) with a Restart now / Later prompt. `server.ts` imports Vite only in dev and takes `WORKPULSE_DIST`.

The main window must stay running (tray). In a browser the bridge is absent and Settings -> Widgets only explains this.

## Gotchas

- **Dates are LOCAL** (`src/utils/dates.ts`: `localDateStr()`, `localTimeStr()`, `rangeStart()`, `lastNDays()`). Logs, tasks and
  workdays store `YYYY-MM-DD` in the user's timezone (UTC+6), so work at 02:00 counts for that day. Never build a date with
  `toISOString().split('T')[0]` (that is UTC), and compare dates as strings, not with `new Date("YYYY-MM-DD")`.
  ISO timestamps (`createdAt`, `completedAt`, `clockIn`, segment times) stay UTC; convert with `localDateOfIso()` before comparing
  to a date. Tests that touch dates set `process.env.TZ = 'Asia/Dhaka'`. Tasks are never rolled over by date (see **Task dates**); the script
  normalises Sheet dates with `Utilities.formatDate` and writes date columns as text.
- **Running clocks**: the screens that take `backlog` (`TodayScreen`, `TasksScreen`, `EndDayDialog`) are `React.memo` with
  `sameTasksIgnoringLiveTime`, so they ignore elapsed-time ticks. Show a running clock with `<TaskClock>`
  (`src/components/tasks/Clock.tsx`), which read live seconds from `src/utils/timerStore.ts`, never `task.elapsedSeconds` in JSX.
  Every handler passed to a memoized screen goes through `useStableCallback` (the `h` object in `App.tsx`), or the memo is moot.
  `ClockBand` ticks itself (`useNow(1000)`) and shows the current time (`formatClock`) and the time left (`formatHms`) with seconds, no worked figure (only the out state says "worked"); App re-renders every 30 s so the next action follows the clock.
- **`leavingRef` guards saves before an import reload**: `handleImportBackup` sets it just before `window.location.reload()`, and the
  pagehide, visibility and 30 s backlog saves skip while it is set. Without it a running timer's pagehide save writes the old
  backlog over the imported one. Any new "write data, then reload" path must set it too.
- **Changing a data type needs a localStorage migration.** Users have saved data without the new field.
  Use the `data-model-change` skill.
- **Unused dependencies** (nothing imports them; remove only if asked): `motion`, `autoprefixer`.
- **Unused stored settings**: `AppSettings.colorMode` and `crtEffect` are kept only so old stored data round-trips; nothing reads them.
- **Gemini model names live in one list**, `GEMINI_MODEL_CASCADE` in `src/utils/geminiModels.ts`, used by the Gemini path of
  `/api/gemini/generate`, `/api/synthesize-eod` and `/api/activity/suggest`. If AI output falls back to templates, the UI shows the reason; check
  these names first.
- **Sample data**: the demo logs, tasks and projects a new user starts with are recognised by their fixed ids
  (`src/data/sampleData.ts`, no field on any record). They carry a "Sample data" label, a banner offers one-click
  "Clear sample data" with Undo, and `unsyncedLogs` never sends them to the Sheet. Never give a real item an id like
  `log-1`/`task-1`/`proj-1`: real ids always include a timestamp.
- **Backups**: Settings → Data & backup writes/imports one JSON file (`src/utils/backup.ts`, including `workdays`; never the Gemini
  key, `lastBackupAt` or the device-only phone settings). `AppSettings.lastBackupAt` (optional, device-only) is set by `handleBackupNow` in `App.tsx` and only feeds the "Last backup" line in Settings.
  **There is no backup reminder banner**: backups are automatic (disk copies, Sheet backup), the file is an optional extra.
  The automatic backups taken before Reset / Start fresh / Fix dates do **not** count, because the data changes right after.
  Start fresh keeps workdays (attendance, not work content).
- **Failures are plain sentences**: AI and Sheet errors go through `src/utils/aiErrors.ts` (`plainAiMessage`,
  `plainSheetMessage`) so no raw "Failed to fetch" reaches the UI; a failed sync toast carries Retry.
- **Durations come only from tracked time** (`minutesFromSeconds` in `src/utils/duration.ts`): no invented defaults or minimums.
  **One exception: activity suggestions** (below). Their minutes are an estimate (`estimateMinutes` in
  `src/utils/activity/time.ts`: a gap over 30 minutes ends a cluster, each cluster counts its span with a 5-minute floor),
  labelled "estimated" and editable before adding. Once added, the log holds a plain number. Do not reuse that estimate anywhere else.
- **Activity quality and automatic logs** (`src/utils/activity/significance.ts`, `learn.ts`, `skipCount.ts`, `quality.ts`): the pipeline's optional `quality` arg drops trivial items (`isNoise`: merge/wip/typo commits, "yes"-style prompts) and scores each suggestion (`scoreCluster`): `log` (worth a log), `maybe` (below `AppSettings.activitySmallestLog`, default 15 min, scaled by `activityDetail`; shown in the Maybe list on Today with Add, never added by itself) or `skip` (counted for System status). `useLiveActivity` (every 10 min while a workday is open, needs the notice and `activityAutoAdd !== false`) adds `log` ones through `handleAddAutoLogs` (origin `auto`, Undo). Deleting an auto log raises that project's bar (`workpulse_autolearn`). `useDayClose` uses the same quality rules. Smoke seeds `activitySmallestLog: 1`.
- **Activity sources are a registry** (`src/utils/activity/registry.ts`; server readers in `src/server/readers/index.ts`): to add an AI tool or source, add a descriptor plus one reader line; Settings, the data notice, the consent signature and evidence text follow. Sources: claude, git (commits + uncommitted), opencode, codex, docs, files (names and times of changed files, `readFileActivity.ts`, works with no AI and no commits). The writer chain (Claude, Gemini, plain template) falls back visibly: `aiResults.ts` + `aiStatus.ts` feed the "AI writer" row of System status, and History's standup has "Rewrite with AI" for template-written, unedited standups (`standupRewrite.ts`, `rewriteStandup`).
- **Activity suggestions** (the Today card, End my day's Suggested logs, and the `ActivitySuggestionsDialog`, which the next action opens
  under 1024 px): the server reads the day's git commits and Claude Code prompts (both sources are on unless switched off) from the folders linked to projects
  in Settings → Projects & tags, and an AI groups them into suggested logs the user ticks and adds. **One log per project**:
  the AI writes one summary sentence per project plus short sub-tasks (saved as the log's `underlyingTasks`, shown as "N sub-tasks"
  on the row and listed in the log form), and splits a project into two logs only for totally unrelated work. Trivial prompts
  ("yes", "go ahead") are left out; items the AI does not place join the task of their folder (`parseAiTasks`) instead of becoming
  rows. The AI is `AppSettings.activityAi` (the shared "AI writer" setting): `'claude'` (default, absent = claude), `'gemini'`, or `'none'` (plain wording, no AI call).
  - **Sources** (`ActivitySource` in `src/utils/activity/types.ts`; switches in `AppSettings`, read by `src/utils/activity/settings.ts`): `claude` (Claude Code JSONL), `git` (commits, plus uncommitted files from `src/server/gitChanges.ts`: names and times only), `opencode` (SQLite, read-only, `src/server/readOpenCode.ts`), `codex` (JSONL sessions, `src/server/readCodex.ts`) and `docs` (Word, Excel, PowerPoint, PDF, OpenDocument: names and times only, never opened, `src/server/readDocuments.ts`). Claude and git are on unless switched off; OpenCode, Codex and docs are read only when on (`activityUseOpenCode`, `activityUseCodex`, `activityUseDocs`). **Auto projects** (`useAutoProjects`, `src/utils/activity/autoProjects.ts`, `activityAutoProjects` absent = on): every 10 min it finds git folders under the watch folder (`activityWatchFolder`, else the common parent of the linked folders) that no project covers, and makes a project for a folder only after real work there today (a commit or uncommitted change, a document, or two AI prompts); `activityIgnoredFolders` are skipped, and "Delete forever" adds a project's folder there.
  - Server side: `src/server/activityReaders.ts` (Claude session JSONL is streamed and files older than the day are skipped by
    mtime; git uses `--all`, per-repo `user.name`, de-dup by hash), `src/server/activityGuard.ts`. Claude's JSONL format is
    internal and can change, so parsing is defensive and unknown lines are skipped. Terminal history is deliberately not supported
    (no timestamps).
  - **Claude Code provider** (`src/server/claudeCli.ts`, `runClaudeJson`): the server runs the user's own `claude -p` (their login, no
    API key) with the prompt on stdin, `--tools ""`, `--strict-mcp-config`, `--disable-slash-commands`, `--setting-sources project`,
    `--no-session-persistence`, `--model haiku`, `--effort low` and a `--json-schema`, from the temp folder (no project instructions).
    Do **not** add `--bare`: it skips keychain reads, so the subscription login stops working. About 4 s and under a cent per call.
    If `claude` is missing, not signed in, slow (60 s) or answers badly, the panel falls back to plain wording with the reason.
    The Gemini key is only sent to the server when Gemini is the chosen AI.
  - Both routes answer only while bound to `127.0.0.1` **and** when the `Host` header is exactly `localhost:<PORT>` or
    `127.0.0.1:<PORT>` (`isStrictLocalHost`; `ALLOWED_HOSTS` does not widen it). Never relax this: the routes read local files.
  - Client side: `src/utils/activity/` (pure, unit-tested: `pipeline.ts` is the whole flow, `suggestions.ts`, `aiTasks.ts`,
    `time.ts`, `sanitize.ts`, `settings.ts`, `sessionStore.ts`) and `src/components/activity/` (`ActivitySuggestionsPanel` holds
    the body; `compact` is the Today/End my day form). The AI only returns `{ text, itemIds[] }`; minutes, project and evidence are
    computed in code from the items. Text is redacted (`redactSecrets`) and clipped before leaving the machine.
  - **Done tasks are items too** (`taskItems` in `suggestions.ts`: id `task:<taskId>`, source `'task'`, in a folder linked to the task's
    project or the key `project:<id>`), so the same grouping, wording and minutes handle them. A suggestion's minutes are the **larger** of the
    done tasks' unlogged timer minutes and the activity estimate (task items do not count toward the estimate). Adding a log whose
    `sourceIds` include `task:<id>` marks that task's time as logged (`markTasksLogged`, in `handleAddLogs`); a task's own timer time is
    not shown as "already on record" for its suggestion. Without folders, done tasks alone still produce suggestions.
  - **Checking.** Nothing is read before the user has accepted the data notice (`'idle'` phase, `noticeSignature`); until then the compact
    panel shows "Check activity". After that the panel checks on its own when it mounts and **every 5 minutes** while visible (today only;
    `AppSettings.activityAutoScan`, absent = on, Settings → Activity suggestions), and "Scan again" checks at once. A background check
    asks the AI again only when the item ids changed (`itemsKey`/`sameAs` in `pipeline.ts`), and never replaces rows the user has ticked or
    edited (`rowTouched`): the new result waits behind a "Refresh" button (`session.fresh`). The result and the user's edits are kept per local
    date for the session in `src/utils/activity/sessionStore.ts` (in memory, gone on reload), shared by the card, the dialog and End
    my day, so reopening or remounting never rescans; App reads `pendingCount(today)` / `checkedToday(today)` from it for the next
    action. The `activity_suggestions` and `activity_today_card` smoke checks enforce all this.
  - Data: `WorkLog.sourceIds` lists the activity ids a log used (they are not suggested again; deleting the log frees them; it is
    never sent to the Sheet and `handleDuplicateLog` clears it). `AppSettings.activityFolders` (the project folder links) **is** in file and Sheet backups; an import validates each link (it must point
    at a project in the same backup) and uses them only when this computer has none. Git commits and Claude prompts are on unless `activityUseGit === false` / `activityUseClaude === false`.
    Adding several logs at once goes through `handleAddLogs`, not a loop over `handleAddLog` (each call would start from the same
    stale `logs`).
- **Projects & tags** (Settings): one "New project" form (name, colour, optional folder with Choose folder or a typed path; a chosen folder fills an empty
  name). `handleAddProjectWithFolder({ name, color, path? })` in `App.tsx` creates or reuses the project (same name, case-insensitive; an archived or
  trashed one comes back) and links the folder in `activityFolders`, saved at once without the Settings Save button (pure part:
  `src/utils/projectFromFolder.ts`, `planProjectWithFolder`, `relinkFolder`; client: `src/utils/pickFolderClient.ts`). A folder already linked to
  another project names it and changes nothing. Each project row shows its folders (last two segments, full path as title) with Change, Remove link and
  Add folder, so **folders are managed from Projects**; Settings -> Activity suggestions only has the source toggles and a read-only folder list.
  Renaming or recolouring changes only the project record, never old logs' `projectName`.
- **Project Trash**: `Project.trashedAt?` (ISO, optional). "Move to trash" (Undo toast) keeps tasks, logs and folder links; Settings -> Trash lists
  trashed projects with Restore and "Delete forever" (confirm dialog with task/log counts; removes the record and its `activityFolders` links, leaves
  tasks and logs). `App.tsx` gives every screen except Settings `liveProjects` (no trashed), so pickers, filters and `byId` lookups skip them and
  rows show "No project"; `activeProjectsOf`/`defaultProject`, the phone snapshot, `mergeInbox` and the activity folders also skip trashed projects.
  Helpers in `src/utils/projects.ts`.
- **Task logging**: `BacklogTask.loggedSeconds` records time already written into a log; the EOD synthesis only logs the rest
  (`src/utils/taskLogging.ts`, `isDoneUnlogged`). **Marking a task done does not create a log** (`handleCompleteTask` in `App.tsx`):
  it waits until the user presses "Log it" on the row (`handleConvertTaskToLog`), picks it on Tasks → "Write timesheet", or
  logs it in End my day step 2. Pausing several timers in a row (End my day) needs `handlePauseTask`'s functional `setBacklog`.
- **Changing the Apps Script means a redeploy.** Any edit to the script (`googleAppsScriptTemplate.ts`, `src/utils/appsScript/*`) only reaches the
  user after they re-paste it and update the **existing** deployment (Deploy → Manage deployments → edit → New version; "New deployment" changes
  the URL). Bump `SCRIPT_VERSION` in `core.ts` and the version checks (`sheetsSync.ts`, `PhoneEmailSection.tsx`) when the app needs new script features, so Settings can say so.
- The Apps Script writes fixed sheet columns and upserts rows by log `Id` (12th column); changing it requires the user to redeploy their script. The app tracks `WorkLog.syncedAt` and `AppSettings.syncTrackingSince` so manual Sync sends only unsynced logs and never re-sends history.
- The server binds `127.0.0.1` by default (`HOST=0.0.0.0` opts in to LAN access, which has no authentication). `/api/sheets/proxy` only forwards to `https://script.google.com/macros/s/...` URLs.
- Never read or print `.env.local` / `.env` (denied in `.claude/settings.json`).

## Coding rules

- **Think before coding.** State your assumptions. If a request is ambiguous, ask instead of guessing.
- **Simplicity first.** Write the minimum code that solves the problem, with no speculative features, options or abstractions.
- **Surgical changes.** Touch only what the task needs. Don't refactor, reformat or "improve" unrelated code.
  Match the existing style (functional components, `React.FC<Props>`, Tailwind classes, theme CSS variables).
- **Goal-driven.** Before starting, say how success will be verified (usually: `npm run lint` passes, and the behavior is
  checked in the browser at http://localhost:3737). Verify before saying it's done, and report failures honestly.

## Workflow

- **Small bug fix**: use plan mode plus the rules above. Don't run Superpowers' full brainstorm/plan flow.
- **New feature or multi-file change**: use Superpowers (brainstorm → plan → execute).
- **Data model change**: use the `data-model-change` skill.
- **UI verification**: use the `webapp-testing` skill with Python Playwright against `npm run dev` (http://localhost:3737).
  Run its helper from the repo root, e.g.
  `python .claude/skills/webapp-testing/scripts/with_server.py --server "npm run dev" --port 3737 --timeout 60 -- python <script>.py`.
  Write throwaway scripts and screenshots outside the repo.
- **Before ending a session**: run the `session-handoff` skill (writes `.claude/HANDOFF.md`).
- A Stop hook runs `npm run lint` after each turn and sends type errors back to be fixed.
